Two things go wrong, and neither lives in the inbox

Scope creep arrives politely

Nobody writes “I would like to change the contract.” They write “can you also just…”, it reads as a favour, and it gets done for free.

Promises go quiet

“I'll get that to you by Friday” is buried under forty messages a week later. The client remembers it. You don't.

What it actually does

  1. Ingest

    Turns the signed contract into scope items, each carrying a span copied character for character. A quote that isn't in the document raises an error rather than being quietly dropped.

  2. Classify

    Reads each message against those clauses. In scope, outside it, a new commitment, or noise — with the line that decides it.

  3. Ledger

    Tracks every promise either side made, resolves “by Friday” into a date in your timezone, and marks what is late.

  4. Draft

    Writes the change-order reply, or the update you owe. Into drafts. Never sent.

What it refuses to do

Three limits, enforced in code and covered by tests — not requested politely in a prompt.

It never sends

Drafts are created and stop there. The Gmail permission it holds would allow sending. The code has no path that does, and a test fails if one appears.

It never invents a number

No fee, price, or percentage reaches a client unless that figure is already in the contract.

It never picks your date

An update about late work leaves the date blank for you. Committing you to a delivery date you never agreed is not its call to make.

Both sides of the same table

A freelancer owes the work. The shop that hired them is owed it. Same contract, same thread, opposite reading of who is late — and the same engine answers both, because whether a request is in scope turns out to be a property of the request, not of who is reading it.

If you do the work

What you promised, what slipped, and which requests were never part of the fee.

If you paid for it

What they promised, what is late, and whether you are about to be billed for something you thought was included.
